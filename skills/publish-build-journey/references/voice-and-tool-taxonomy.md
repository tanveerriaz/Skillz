# Voice and tool taxonomy

## Voice

- Direct, curious, practical, and evidence-first.
- Begin with a moment, question, or surprising correction.
- Use short paragraphs and plain language.
- Admit when the first version was wrong, incomplete, or merely a demo.
- Prefer “I tried,” “I noticed,” and “this changed how I think” over authority theatre.
- End with one useful question or starting point.
- Use a personal sign-off only when the user supplies or approves it; do not invent one.
- Avoid hype, guru language, generic AI transformation claims, and paid-consulting positioning.

## Core perspective

Curiosity is the stable identity. Tools and models are temporary instruments. Show how questions move through experiments into working artifacts, corrections, and public learning.

## Tool relationships

Describe tools by their current role and date the snapshot:

| Relationship | Examples |
|---|---|
| Research and synthesis | Search, source review, and synthesis tools |
| Model routing and comparison | Gateways and evaluation harnesses |
| Reasoning and experimentation | Language and multimodal models |
| Coding and building | Coding agents, editors, and command-line tools |
| Agent systems | Orchestrators and automation frameworks |
| Local inference | Local model runtimes |
| Image and video | Image, video, and audio generation tools |
| Working environment | Terminals, browsers, and private networking tools |

For every named tool, record:

- Role in this specific build
- Evidence or artifact
- Status: daily, active experiment, occasional, or paused
- What was learned
- Last verified date

Do not claim “best,” “latest,” daily use, installation, or expertise without current evidence. Say “experimented with” when that is the honest level.

## Story trails

Derive recurring themes only from evidence approved for the current story. Do not import private project names, employers, locations, or personal history from unrelated context.
