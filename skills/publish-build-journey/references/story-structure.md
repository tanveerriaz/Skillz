# Chronological story structure

Use this sequence unless the evidence clearly calls for a shorter form.

## 1. The question

Open with the concrete thing the author noticed, not a trend forecast. Prefer “I wanted to know whether…” or a specific moment over “AI is transforming everything.”

## 2. Why now

Name the event, tool, constraint, conversation, or frustration that made the question timely. Date changing tool/model claims.

## 3. The first attempt

Explain the initial approach and why it seemed reasonable. Include the first visual when it helps the reader see the gap.

## 4. The build sequence

Describe decisions chronologically. Identify each tool or model by the job it performed, not as a logo list.

Example:

```text
Question → research → visual direction → implementation → verification → deployment
```

## 5. Where it broke

Name the mismatch, failure, weak assumption, or missing truth. Do not create artificial drama. Small corrections often reveal the most transferable judgment.

## 6. The correction

Show what changed and why. Include before/after evidence when available.

## 7. The working artifact

Link the public product, repository, demonstration, or reproducible result. Label mock data, fictional products, generated media, and snapshots.

## 8. What changed in my thinking

State the lesson in the author's voice. Connect it to a broader working principle only when the evidence supports the connection.

## 9. Where you can begin

Offer one small first step: a prompt, exercise, public guide, repository, or three-step path. Avoid overwhelming beginners with the full stack.

## 10. Build receipt

Record:

- Status and capture date
- Tools/models and their roles
- Verified public URLs
- Test or deployment evidence
- Image provenance and disclosures
- Material intentionally kept private

## Length variants

- **Field note:** 500–900 words; one question, one correction, one starting point.
- **Build journey:** 1,000–1,800 words; full chronology with 3–6 visuals.
- **LinkedIn adaptation:** 180–450 words; preserve the moment, correction, lesson, and public URL. Link to the canonical website story.

Create the website version first. Treat social posts as adaptations, never as the only durable copy.
